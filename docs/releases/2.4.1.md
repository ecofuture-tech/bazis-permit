# bazis-permit 2.4.1

Requires bazis 2.4.2.

## Fixes

- **`makemigrations` of a project wrote a migration into the installed package** when the
  languages of the project (`BS_LANGUAGES`) were not English and Russian, for example the
  default English only: the translated field `name` of `Role` and `GroupPermission` had a
  column per language of the project, while the migrations of the package have `name_en`
  and `name_ru`. Now the field always has these two columns, in the order of the project's
  languages (the first one is the fallback). In a language without a column the name is read
  and written in its base language (`en` of `en-us`) or the fallback language. New in
  `bazis.contrib.permit.models_abstract`: `LANGUAGES`, `translated_languages(*languages)`,
  `translated_column(name, languages, language=None)` and `translated_attrsetter`.

Found by the evals of bazis-cli.

## Upgrading a project that hit the bug

If `makemigrations` of the project wrote a migration into the installed package and it was
applied, the database lacks the `_ru` columns. The upgrade removes the file of that
migration, its record stays:
`SELECT name FROM django_migrations WHERE app = 'permit' AND name > '0007_name_en_blank';`
returns it. Then add the columns back and forget that migration:

```sql
ALTER TABLE permit_role ADD COLUMN IF NOT EXISTS name_ru varchar(255) NOT NULL DEFAULT '';
ALTER TABLE permit_grouppermission ADD COLUMN IF NOT EXISTS name_ru varchar(255) NOT NULL DEFAULT '';
DELETE FROM django_migrations WHERE app = 'permit' AND name > '0007_name_en_blank';
```
