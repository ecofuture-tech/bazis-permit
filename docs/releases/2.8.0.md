# bazis-permit 2.8.0

## Security

- **An item the user cannot view is 404, not 403.** The routes of an item answered 404 for
  a missing id and 403 for an existing item the user cannot view, so anyone could tell
  which ids exist. `PermitRouteBase.get_queryset_for_item` now looks the item up among the
  objects the user can view (`restrict_queryset` for `view`, a subquery of the same query;
  with the lock of a write the lock stays on the item): an item he cannot view is not
  found, the 404 of the core for a missing item, with the same detail in the language of
  the request and the same queries. It covers retrieve, update, delete, the relationships
  endpoints, `schema_retrieve`, `schema_update`, the transits and `schema_transit` of
  bazis-statusy, and any custom action that takes its item with `set_item` or `get_item`.
  The anonymous writes look the item up first: 404 for an item the anonymous user cannot
  view, 403 for one he views. An item the user views but cannot change or delete is still
  403, as is the list of a model he has no permission on.

  The read of the response after a create, an update or a transit (the item the route
  already holds) is not restricted again: a create or an update that makes the item
  invisible to its author is refused with 403 and rolled back, as before (the schema of the
  response requires the `view` permission); a bazis-statusy transit that hides the item is
  kept and answers 204, as before.

## Breaking changes

- The status above: a client that told "forbidden" from "not found" on the routes of an
  item gets 404 for the items the user cannot view.

## Fixes

- **The selector `self` with a selector source of several objects found nothing.**
  `self` matched the object whose primary key is the source, `get_selector_for_user(user)`,
  taken as one object: a source that returns a list or a queryset (the teams the user
  watches) gave no primary key and the permission matched nothing. It matches each of the
  objects now (`pk` in the list); an empty source still matches nothing. This is the
  known defect the guide of 2.7.1 mentions.
