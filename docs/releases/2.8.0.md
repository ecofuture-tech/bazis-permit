# bazis-permit 2.8.0

## Security

- **An item the user cannot view is 404, not 403.** The routes of an item answered 404 for
  a missing id and 403 for an existing item the user cannot view, so anyone could tell
  which ids exist. They answer now as for a missing item, 404 `Item not found`: retrieve,
  update, delete, the relationships endpoints, `schema_retrieve`, `schema_update`, the
  transits and `schema_transit` of bazis-statusy, and any custom action that takes its
  item with `set_item`. `PermitRouteBase.set_item` checks the `view` permission of the
  item it takes (anonymous writes included: 404 for an item the anonymous user cannot
  view, 403 for one he views). An item the user views but cannot change or delete is
  still 403, as is the list of a model he has no permission on.

## Breaking changes

- The status above: a client that told "forbidden" from "not found" on the routes of an
  item gets 404 for the items the user cannot view. A custom action that took its item
  with `get_item` gets no such check: take it with `set_item`.

## Fixes

- **The selector `self` with a selector source of several objects found nothing.**
  `self` matched the object whose primary key is the source, `get_selector_for_user(user)`,
  taken as one object: a source that returns a list or a queryset (the teams the user
  watches) gave no primary key and the permission matched nothing. It matches each of the
  objects now (`pk` in the list); an empty source still matches nothing.
