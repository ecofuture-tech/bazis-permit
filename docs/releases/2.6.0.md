# bazis-permit 2.6.0

Requires bazis 2.7.0.

## Features

- **Selectors by many-to-many and reverse relations.** A selector may be a many-to-many
  field of the model or a reverse relation of a selector source, named by its
  `related_name` (a foreign key or many-to-many field of the user, of an organization...),
  also at the end of a path of relations:

  ```
  entity.meeting.item.view.participants      # Meeting.participants = ManyToManyField(User)
  entity.team.item.view.members              # User.team = ForeignKey(Team, related_name='members')
  entity.team.item.view.watchers             # User.teams_watched = ManyToManyField(Team, related_name='watchers')
  entity.meeting.item.view.team__members     # the meetings of the team of the user
  ```

  The object matches when the selector value (the user, or what `get_selector_for_user` of
  the selector source returns) is one of its related objects. The condition is an `EXISTS`
  subquery (`<selector>__pk=<value>`), so an object matches once whatever the number of its
  related objects, also when several permissions match it (`view.author` and
  `view.participants`). It applies to every operation (`view`, `change`, `delete`,
  `check`, custom operations such as the transits of bazis-statusy:
  `item.transit.participants.<status>.<transit>`) and to the field permissions
  (`field.view.participants.description.disable`).
- `PermitModelMixin.get_selector_fields` returns these relations too (by their accessor
  name for a reverse relation).

## Behavior changes

- A permission whose selector names a many-to-many field or a reverse relation to a
  selector source matched nothing before (with the warning `Permit: ... has no selector`);
  it now grants what it says. Check the roles for such permissions before upgrading.

## Performance

- The subquery uses the unique index of the automatic through table of a many-to-many
  field and the index of the foreign key of a reverse relation. A custom `through` model
  needs a unique constraint or an index on its two foreign keys.
- `autogen_selectors_fields` (the generated selector arrays with GIN indexes) is not needed
  for these selectors and is unchanged: it still covers the forward relations only.
