# bazis-permit 2.5.0

Requires bazis 2.7.0.

## Security

- **The core checks the related objects for every route.** Bazis 2.7 lets a created or
  changed item reference only the objects the default route of the related model shows
  (`restrict_queryset` of `PermitRouteBase` for a permission-protected model: `view`, and
  `change` for a reverse relation) and shows in `included` only the visible objects, for
  every route, not only the routes of bazis-permit with
  `BAZIS_PERMIT_RELATIONS_VIEW_CHECK` on. The check of the package
  (`PermitRouteBase.check_relations_access`) is removed: it is the same check, now always
  on. A reference the user may not make fails with `403 ERR_RELATION_ACCESS` and the pointer
  `/data/relationships/<field>`; an invalid identifier fails with `400` (the error of the
  core instead of `ERR_RELATION_ID`).
- **`restrict_queryset` never fails without a user.** The core calls it on the class with
  the user of the calling route, None for a route without a user (not a `UserRouteBase`,
  e.g. the roles route or a public route). Then it restricts for the authenticated user of
  the request (`UserMixin.CTX_USER_REQUEST`) and, without one, as for an anonymous user (the
  roles for anonymous users); a user without the roles of bazis-permit (an anonymous user
  model without `AnonymousUserPermitMixin`) sees nothing. Before, such a request failed with
  403 "User instance anonymous or missing the role_current property".

## Breaking changes

- **The related objects are always checked.** A project that kept
  `BAZIS_PERMIT_RELATIONS_VIEW_CHECK` off (the default) now gets `403 ERR_RELATION_ACCESS`
  for references to objects the user cannot view (or, for a reverse relation, change). Give
  the users the permissions, or turn the check off for a route with
  `relation_targets_check = False`.
- **A route without a user links only what an anonymous user sees**: the routes of
  bazis-users know the user, a plain `JsonapiRouteBase` does not.
- `restrict_queryset(qs, access_action, user=None, permit=None, **kwargs)` accepts
  `**kwargs`; an override in a subclass should accept them too.
- Removed `PermitRouteBase.check_relations_access`, `_check_related_access` and
  `_relation_ids`.

## Deprecated (removed in 3.0)

- `BAZIS_PERMIT_RELATIONS_VIEW_CHECK` has no effect. Setting it emits a
  `DeprecationWarning` and `permit.W001` (`manage.py bazis_doctor`) now reports that it is
  set; remove it.
- `PermitRouteBase.relations_view_check` emits a `DeprecationWarning`; `False` works as
  `relation_targets_check = False` of the core, `True` does nothing.

## Unchanged

- The schemas of the included objects are still built per object with its permissions
  (the fields it shows, and for the update schema the `change` permission): the core
  filters the included objects, the package restricts their fields.
